Backend interface blueprint

模型服务接口契约

这是 ticket 中建议落地的资源命名和边界；本 HTML 不会调用真实接口。

GET /api/inference/configuration

读取当前模型服务

Inference 模块独立读取 Configuration、Route、Provider 三类资源，以及脱敏后的 API key 状态。

PUT /api/inference/configuration

保存完整配置

以聚合请求原子更新平台级 Configuration、Route 绑定和可复用的 Provider 连接资源。

POST /api/inference/configuration/verify

验证未保存草稿

不写数据库、不生成 Session；分别验证 Chat Completions 与 1536 维 Embeddings。

POST /api/setup

原子完成首次设置

请求可携带 inferenceConfiguration；User、Workspace、Configuration、Route 和 Provider 在同一事务中保存。

数据边界：模型服务不再从通用 settings key/value 中读取；settings 只保留语言、主题等平台偏好。MVP 按平台级别生效，且不考虑历史数据迁移。

        
聚合边界：inference_routes 负责把 Configuration 的 capability 绑定到 Provider 与 model；Provider 不再持有 inference_configuration_id，因此可以被多个配置复用。后端使用 InferenceConfiguration、InferenceRoute、InferenceProvider 和 IInferenceConfigurationAppService。Settings controller 不再承载模型服务接口。
